# TenderAI

Базовый пайплайн технического сопоставления четырёх SKU эластомерных помп с требованиями закупок.

На этом шаге есть инвентаризация файлов, разбор таблиц, структурированные характеристики и кодовая проверка ограничений. Векторного канала нет: у каждого объекта сохранён текст для будущего энкодера и разобранные признаки, а поле `vector` равно `null`. Модель не ставит статус `match`.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
pytest

python -m tenderai run \
  --dataset dataset_zakupki \
  --out runs/baseline \
  --tenders 0128200000125006876,0373200087824002359
```

Пустой `--tenders` обрабатывает весь набор. Номера закупок передаются строками, как в папках датасета.

GPT-Luna в этот прогон не вызывается. Клиент лежит в `src/tenderai/llm.py` и включается только вместе с идентификатором модели в конфиге. Пример конфига без секретов: `config.example.json`.

## Выход прогона

- `prepared/` — характеристики SKU и требования с цитатами
- `representations/structured.json` — что пойдёт в энкодер; числа и единицы лежат в `features`
- `comparisons/checks.json` — требование × SKU: `match`, `mismatch` или `unknown`
- `comparisons/positions.json` — позиция × SKU
- `comparisons/tenders.json` — сводка закупка × SKU
- `errors.json` — сбои разбора, отдельно от статуса соответствия
- `usage.jsonl` — журнал этапов

Пара, для которой не нашлась характеристика, получает `unknown` и причину `not_aligned`. Пробел в файле закупки не даёт сводке статус `mismatch`.

## Источники требований

Требования извлекаются детерминированно из трёх видов источников:

- таблицы описания объекта закупки (XLS/XLSX и таблицы DOCX), в том числе с заголовками «Наименование показателя / Значение показателя»;
- XML извещения ЕИС: блоки `characteristicsUsingReferenceInfo` с именем, единицей OKEI и значениями (`qualityDescription`, `concreteValue`, `rangeSet` с операторами).

Дубликаты одной характеристики между копиями извещения снимаются по паре «позиция + имя».

## Эксперимент H4 — покрытие прозовых закупок

Детерминированное извлечение подняло охват с 4 до 6 закупок из 10: добавились `01`, `07`, `10`
(их требования лежали в DOCX-таблице и в XML извещения, а не в прозе). Всего требований 37 → 107.
Закупки `02`, `03`, `05`, `06` остаются с нулём требований — это настоящая проза в PDF и DOC, зона
для извлечения через GPT-Luna. Прогон: `runs/h4`.

## Что измерять следующим

Каждое добавление гоняется на тех же `--dataset` и `--tenders`. Оставляем его, только если на ручной выборке растёт качество или падают токены.

1. GPT-Luna на `02`, `03`, `05`, `06` — остаток прозы, который код не берёт (вторая половина H4).
2. Вектор на характеристику и требование вместо лексического ключа.
3. Reranker, OCR и повтор с проверкой цитаты — отдельными флагами.

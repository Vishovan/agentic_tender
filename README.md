# TenderAI

Воспроизводимый серверный пайплайн технического сопоставления десяти закупок эластомерных инфузионных помп с четырьмя артикулами SKU (`CT0050L`, `M275-07`, `MC1248L`, `MS5248M`) в общем латентном пространстве.

- **Латентное пространство (`H2`):** открытый русскоязычный энкодер `ai-forever/FRIDA` (`1536d`, асимметричные префиксы `search_query:` / `search_document:`) кодирует предметные слоты характеристик SKU и требований в [runs/full/representations/structured.json](runs/full/representations/structured.json). Ранги косинусной близости объединяются с лексическим поиском через `Reciprocal Rank Fusion (k = 60)` и фильтр метрологических квалификаторов.
- **Строгая проверка ограничений (`H3`, `H10`):** числа, интервалы, наборы скоростей, единицы измерения и отрицания не растворяются в векторе, а проверяются детерминированным чекером `check_constraints`. Несопоставленные слоты и пустые ячейки паспорта дают честный `unknown`, а битые файлы выгрузки ЕИС фиксируются в `errors.json` и защищают закупку от ложного `mismatch` (`coverage_gap`).
- **Извлечение из грязных документов (`H4`, `H9`):** таблицы XLS/XLSX/DOCX, архивы RAR (`bsdtar`), сканы без текстового слоя (локальный Apple Vision OCR по флагу пустого текста) и прозовые ТЗ через рабочую модель `gpt-5.6-luna` (`cursor-sdk`).

## Быстрый старт и воспроизведение

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
pytest -v

# Полный прогон по 10 закупкам × 4 SKU (FRIDA + RRF + OCR + RAR + кэш GPT-Luna)
PYTHONPATH=src python -m tenderai run \
  --dataset dataset_zakupki \
  --out runs/full

# Абляции и замеры на проверенной выборке (H1, H2, H3, H6, H9, H10)
python scripts/experiments.py

# Сводная таблица расхода токенов (опционально --tariff-per-1k <USD>)
python scripts/token_table.py
```

Для запуска только на выбранных закупках передайте `--tenders 0372100048826000117,0321200014126000201`, для переключения режима выравнивания — `--align-mode lexical|dense|hybrid_rrf`. Пример конфига без секретов: `config.example.json`.

## Структура выхода (`runs/full/`)

- `prepared/` — нормализованные характеристики SKU (`144`) и требования закупок (`225`) с дословными цитатами и локаторами (`Span`).
- `representations/structured.json` — сохранённые `1536`-мерные векторы `FRIDA`, входные строки энкодера, структурированные признаки `Constraint` и привязка к исходным объектам (`369` записей).
- `comparisons/checks.json` — `900` проверок «требование × SKU» (`match`, `mismatch`, `unknown`) с объяснением и цитатами обеих сторон.
- `comparisons/positions.json` — `76` позиционных вердиктов (`2 match`, `60 mismatch`, `14 unknown`).
- `comparisons/tenders.json` — сводная таблица `10 закупок × 4 SKU = 40` решений (`CT0050L` полностью закрывает закупки `07` и `10`, `7/7` требований).
- `errors.json` — `3` реальных файла с сохранённым JSON-ответом об ошибке ЕИС (`saved_error_response`), отдельно от статусов соответствия.
- `usage.jsonl` — поэтапный журнал вызовов, токенов, кэша и времени выполнения.

## Документация и отчёты (LaTeX / PDF / Markdown)

- `docs/final_report.tex` (`docs/final_report.pdf`) — полный итоговый отчёт по заданию: архитектура, обоснование компонентов, латентные представления, аудит выборки, таблица «baseline против итога», токены/стоимость, матрица `10 × 4` и сценарий 5–10-минутной демонстрации.
- `docs/progress_report.tex` (`docs/progress_report.pdf`) — ход работы и статус гипотез `H1`–`H10`.
- `docs/reading_notes.tex` (`docs/reading_notes.pdf`) — разбор литературы по RAG, `FRIDA`, `RRF` и `LoRA` применительно к задаче.
- `eval/REPORT.md` и `eval/held_out_draft.json` — ручной аудит отложенной выборки (`15` пар `G01`–`G15` и прозовый срез `E01`).
